# 일감 템플릿 · 자동 승인 규칙 · 명령 팔레트 (5-3)

## 1. 일감 템플릿
- 자주 쓰는 지시를 **이름 · 종류 · 지시문 틀 · 기본 우선순위 · 필요한 키 · 승인 방식**으로 저장한다.
  - 종류: `revision`(앱 수정) · `lab`(실험) · `tool`(카드로 바로 생성). **출시·새 앱은 템플릿으로 보내지 않는다**(출시는 `enqueue_release_job` 전용).
  - 빈칸: `{{이름}}`(꼭 채움) · `{{이름=기본값}}`(비우면 기본값). 값 안의 `{{…}}` 는 다시 풀지 않는다.
  - 승인 방식: 설정 기본값 / 바로 시작 / 계획 먼저(5-1).
- 기본 템플릿 5개는 코드(`lib/factory/jobTemplates.ts`)에 있다: 웹 배포 · 스토어 문구 수정 · 의존성 업데이트 · 버그 재현 후 수정 · 측정만(실험). 끝에 **일감 작성 규칙**(측정은 실험 일감으로, e2e 는 마지막에 한 번만, 요청하지 않은 부분은 바꾸지 않기)이 붙는다. 내 템플릿은 `factory_job_templates` 에 저장한다(기본 이름과 같은 이름 불가).
- 화면: 통제실 [일감] 탭 `📋 템플릿으로 보내기`(내 템플릿 만들기·지우기 포함), 앱별 대기열의 `[템플릿으로 보내기]`.
- 커넥터: `list_templates`, `enqueue_from_template(template, values, appSlug?, priority?, aiEngine?)`.
- 등록은 기존 함수(`enqueueWithId`·`enqueueLabJob`·`enqueueToolJob`)를 그대로 불러서 같은 검사를 받는다. 일감의 `templateId` 는 서버 안 호출의 `internal` 인자로만 붙는다(외부 도구 인자로는 못 정함).

## 2. 자동 승인 규칙 (기본 모두 꺼짐)
`factory_settings.autoApproveRules`(JSON). 일감이 등록된 직후 `maybeAutoApprove` 가 평소 승인과 같은 길(`adminAction approve`)로 승인한다.

| 규칙 | 조건 |
| --- | --- |
| `lab` | 실험 일감 |
| `tool` | 비용 한도(일·월) 안의 도구 일감(한도를 넘으면 평소대로 사람 확인) |
| `docs` | 수정 일감 지시문이 "문서만"이라고 밝히고 코드 파일·마이그레이션·의존성 말이 없을 때 |
| `template` | 설정에서 지정한 템플릿으로 보낸 일감 |

- **출시 일감(kind=release·releaseKind)과 새 앱은 어떤 규칙으로도 자동 승인하지 않는다.** 서버 배포는 일감이 아니라 사람이 [배포]로만 한다.
- 자동 승인된 일감은 `autoApprovedBy` 에 규칙이 남고, 일감 로그·[현황] `⚡ 자동 승인된 일감`(24시간)·일감 상세에 표시되며 텔레그램으로 한 줄 알린다.
- `template` 규칙의 템플릿 승인 방식이 "계획 먼저"이면 자동 승인 뒤에도 계획 단계(5-1)를 거친다.

## 3. 명령 팔레트 (⌘K / Ctrl+K)
- 통제실과 스튜디오(관리자만)에서 열린다. 오른쪽 아래 `Ctrl+K 검색·명령` 단추로도 연다.
- 검색: 앱 · 일감(최근 40) · 정비 대화(최근 20) · 카드 · 템플릿 · 설정 항목 · 탭. 낱말이 모두 맞아야 하고 공백은 무시한다.
- 바로 실행: `한 컷 싹이 단독 짤 2장`(앱 → 대상 → 카드 → 장 수 → 도구 일감 등록, 승인은 평소 규칙), `감독 상태`, `지금 업데이트`, `<앱> 스튜디오 열기`, 감독 일시 정지·재개.
- **확인 창을 한 번 더 띄우는 동작**: 서버 배포 · 배포 되돌리기 · 감독 재시작. 배포·되돌리기는 팔레트에서 바로 실행하지 않고 해당 화면(할 일 · 배포 기록)으로 이동시킨다. 실행은 그 화면의 버튼에서 한 번 더 확인한다.
- 자료: `GET /api/admin/factory/palette`(읽기 전용). 항목 조립·검색·명령 풀이는 `lib/factory/palette.ts`(DB 없음).
