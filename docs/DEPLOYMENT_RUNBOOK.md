## 정상 운영 터미널에서 재개할 순서

이 절차는 사용자가 이미 승인한 배포를 정상 권한의 운영 터미널에서 재개하기 위한 것이다. 각 단계가 실패하면 다음 단계로 넘어가지 않는다.

1. **기존 상태 기록과 유휴 확인**
   - 통제실의 현재 일시 정지·자동 업데이트·자동 배포 설정을 기록한다.
   - 새 앱 일감을 일시 정지하고 감독 자동 업데이트를 잠시 끈다. 정비·앱·출시 작업이 진행 중이면 끝날 때까지 기다린다. 승인된 정비 지시나 배포 요청도 없어야 한다.
   - PID 파일만으로 유휴라고 판단하지 말고 통제실의 작업 목록·정비 대기열과 실제 프로세스를 확인한다. 기존 작업을 강제 종료하지 않는다.
2. **최신 소스와 로컬 검사**
   - `C:/Users/kju90/dev/buyoungsil-dev-web`에서 원격 main을 fetch한다. 원격이 앞서 있으면 이번 로컬 통합 커밋을 최신 main 위로 rebase하고 충돌을 해결한다. 강제 push하지 않는다.
   - `npm run test:ai-harness`, 전체 TypeScript 검사, 각 감독 `.mjs`의 문법 검사를 실행한다. 이 정상 환경에서는 실프로세스 시험 4개도 통과해야 한다.
   - 설치된 Prisma Client를 새 스키마로 생성한다. Node/Prisma 버전과 기존 배포의 의존성을 확인한다.
3. **실제 CLI와 전환 시험**
   - 운영 소스와 별도의 임시 Git 프로젝트에서 CLI 설치·로그인, Claude/Codex 각각의 파일 작성, 검증, 세션 재개, 다른 AI로 인계, 취소, 잠금을 시험한다.
   - 토큰·비밀번호·운영 파일은 시험 폴더에 넣지 않는다. full-access 또는 훅 신뢰 우회를 사용하지 않는다.
   - CLI 실행 실패나 검증 실패를 성공으로 기록하지 않는다. 자동으로 다른 AI로 대체하지 않는다.
4. **DB와 서버 복구 수단 확인**
   - 서버 `serverpc`의 `~/git-server/work/developWeb`과 현재 `developWeb` 컨테이너·이미지·헬스체크를 확인한다. 환경변수 값은 출력하지 않는다.
   - 실제 PostgreSQL 컨테이너·DB를 확인한 후 보호된 서버 경로에 DB 백업을 만들고 복구 가능한지 확인한다. 컨테이너명·계정·DB명을 추측하지 않는다.
   - Prisma migration status를 확인한다. 이번 `20261016090000_add_factory_ai_engine` 외에 예상하지 않은 미적용 마이그레이션이 있으면 먼저 내용을 검토한다.
   - 기존 이미지의 복구 태그와 이전 배포 커밋을 보관한다. DB 열은 롤백에서도 삭제할 필요가 없다.
5. **기존 경로로 소스 반영과 배포**
   - 검사한 커밋을 GitHub origin main에 일반 push한다. 새 감독 프로그램이 먼저 자동 적용되지 않도록 앞 단계의 업데이트 정지를 유지한다.
   - 기존 배포 절차의 대상은 `serverpc:git-server/repo/developWeb.git`이다. 검사한 동일 커밋이 GitHub main에 있는지 확인한 뒤 배포한다.
   - 기존 Docker 시작 명령은 `prisma migrate deploy` 후 앱을 시작한다. 빌드 성공뿐 아니라 추가 마이그레이션 적용·앱 시작·헬스체크를 확인한다.
   - 실패하면 기존 코드/이미지로 복구하고, 실패 로그는 민감한 값을 가려 기록한다. 작업 파일이나 DB 데이터를 지우지 않는다.
6. **감독 프로그램 업데이트와 홈페이지 시험**
   - 기존 통제실 업데이트 경로로 실행본을 갱신한다. 실행본을 개발본으로 덮어쓰거나 실행기를 대화 세션의 백그라운드로 바꾸지 않는다.
   - 새 감독 프로그램의 커밋·시작 시각·폴링 성공을 확인한다.
   - 기존 Claude 일감 하나의 회귀 시험과 Codex 일감 하나의 선택→실행→검증→보고를 확인한다. 정비 AI 전환 시 `sessionId`와 `codexSessionId`가 섞이지 않는지도 확인한다.
   - 홈페이지 새 앱 승인·수정 입력·출시 선택·정비 입력에서 AI가 표시되고 실행 중 변경이 거부되는지 확인한다.
7. **기존 운영 설정 복원과 기록**
   - 성공 후 처음 기록한 운영 설정에 맞춰 접수·자동 업데이트를 복원한다. 원래 꺼져 있던 자동 배포를 켜지 않는다.
   - 실제 배포 커밋, DB migration 상태, 이미지 복구 태그, 감독 커밋, 시험 결과를 `CLAUDE_CODE_HANDOFF.md`에 기록한다.
